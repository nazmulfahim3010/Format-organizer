# SmartDoc — working rules

Template-driven DOCX generation. Users upload any .docx template (any language, incl. RTL and complex scripts such as Bangla), paste content, and get a DOCX that follows the template's own styles, headers, footers, numbering and page setup. No paid AI at runtime.

## Non-negotiable design rules
1. Template is the base document: clear the body, keep the final sectPr, headers, footers, numbering, styles, page setup. Exception (approved by the user, 2026-11-06): when the profile's `keep_template_layout` is on, keep the body up to the template's first heading that has text (first-page layout) and fill `{{PLACEHOLDERS}}` there and in headers/footers; the user's content replaces everything after it.
2. FormattingProfile maps roles (heading_1..n, body, list_bullet, list_number, caption, table styles) to template style ids, with an `origins` dict recording where each rule came from. Approved profile versions are immutable; edits create a new draft.
3. Content is a JSON tree of boxes (section, paragraph, list, table, figure) with `schema_version`. Inline markup: `**bold**`, `*italic*`, `^sup^`, `~sub~`, backslash escapes.
4. Pasted source formatting is DISCARDED. Never copy fonts, sizes or colours from pasted content.
5. Captions use real SEQ fields with cached numbers. Lists use real Word numbering. Heading numbering comes from the template or a generated multilevel list linked to heading styles.
6. Write OOXML children in schema order (rPr, pPr, tblPr, tcPr).
7. Complex scripts: cs/eastAsia fonts, bCs/iCs/szCs, rtl, bidi paragraphs, bidiVisual tables. Caption labels (Table, Figure, Source, Note) configurable per profile.
8. Validator: no percentage score. Each check is passed/warning/failed/info/manual, kind auto/visual.
9. Uploads are hostile: check extension, ZIP signature, size, ZIP bombs, macros/ActiveX, DOCTYPE/ENTITY, remote attachedTemplate, path traversal, encrypted entries BEFORE parsing. Re-encode images. PDF export: LibreOffice per call, throwaway profile, timeout, stripped env.
10. Ownership checks return 404. Passwords use scrypt. Tokens are HMAC-signed with expiry.

## Stack
Backend `backend/`: Python 3.10+, FastAPI, SQLAlchemy 2 + SQLite, pydantic v2, python-docx, lxml, Pillow.
Frontend `frontend/`: React 18, TypeScript, Vite, Tailwind 3, docx-preview.

## How to work
- Phased delivery; finish and verify one phase before the next. Plan lives in `PLAN.md`.
- Test-first for the engine. Fixture templates are generated by `backend/tests/make_templates.py` (default, university, messy, bangla, twocol, rtl).
- Verify layout by RENDERING (DOCX → PDF via LibreOffice → rasterize → inspect). Never claim layout works from XML alone.
- Run the full suite after every phase: `cd backend && python -m pytest -q`; frontend `cd frontend && npm run build`. Never mark a phase done with failing tests.
- If a tool/package is missing, say so and state what was not verified. Never fake a result.
- Small commits, one per task, clear messages.
- Keep README.md honest: install, run, test, verified vs not, known limitations (no TOC/equations/citations yet; merged cells may be split; docx-preview approximate; AI help is a later optional phase).
